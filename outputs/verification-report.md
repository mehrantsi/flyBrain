# FlyBrain native engine verification report

Date: 2026-08-16

Status: historical neural-engine-only checkpoint. It is preserved as an audit record; the current
embodied v783 implementation, test counts, and scientific boundary are documented in `README.md`.

## Outcome

The project is now canonically located at `/Users/mehran/dev/flyBrain`. A compatibility symlink at
the original Codex workspace path points to the new location; there is only one project copy.

The production engine has been ported to native Rust with direct Metal compute through the maintained
`objc2-metal` bindings. Python is retained only for the Parquet-to-CSR compiler and independent
Brian2/NumPy/MLX verification. At this checkpoint, FlyGym and the virtual world remained outside
the milestone.

The native engine runs one biological second of the complete v630 model in 0.4815 wall-clock seconds
on the M3 Max, or approximately 2.08× real time. It allocates 94,238,272 bytes of Metal buffers.

## Native implementation

- Strict Rust NPY v1 reader and hashed CSR pack loader, with no unsafe parsing.
- Rust float64 reference engine using the exact two-exponential state update.
- Embedded MSL kernels hosted through `objc2-metal 0.3.2`.
- Source-driven sparse CSR propagation with deterministic `int32` contact accumulation.
- Brian-compatible update, threshold, delayed-synapse/input, reset, and refractory ordering.
- Chunked command submission; the default is configurable and 1,000 ticks was fastest in the final
  one-second check.
- Deterministic counter-based Bernoulli stimulus shared by Rust and Python.
- Atomic native result directories with IDs, counts, rates, final state, parameters, and SHA-256
  hashes.

The hot simulation path is entirely Rust/Metal. It does not call Python or MLX.

## Performance

Machine: Apple M3 Max, 16 CPU cores, 64 GB unified memory, macOS 26.5.

The final materialized v630 run used 1,000-tick command chunks:

- 10,000 steps at `0.1 ms` each;
- 0.48149925 seconds of measured native execution;
- realtime factor 0.48149925, or approximately 2.08 biological seconds per wall second;
- 94,238,272 explicitly allocated Metal bytes;
- 16,796 spikes across 383 active neurons.

Chunk-invariance checks produced exactly 16,796 spikes with chunk sizes 1, 32, 256, and 1,000. Their
measured times were approximately 2.63 s, 0.588 s, 0.503 s, and 0.484 s respectively, confirming that
host synchronization—not neural arithmetic—was the principal bottleneck in the initial MLX host.

These are single-machine engineering measurements, not a statistical benchmark study.

## Boundary

This checkpoint verified the point-neuron/connectome engine, not an uploaded animal. The current
project now adds a body, world, partial sensory encoders, and explicitly engineered motor mappings;
it still does not recover the VNC, donor state, memories, or Eon bridge. The runtime uses the Apple
GPU through Metal; the separate Apple Neural Engine remains a possible target only for dense vision
or policy modules.
